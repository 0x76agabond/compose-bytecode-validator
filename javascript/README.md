# Compose Bytecode Validator

`compose-bytecode-validator` is the WebAssembly runtime for Compose bytecode
storage validation. It compares a facet's runtime bytecode with the canonical
full-diamond Virtual Storage Layout (VSL) generated from Solidity source.

It is intended to be called by Compose tooling. Consumers need Node.js, but do
not need Rust, Cargo, or `wasm-pack`.

## Install

```sh
npm install compose-bytecode-validator
```

## Usage

```ts
import { validateStorage } from "compose-bytecode-validator";

const report = validateStorage({
  bytecode: "0x...", // deployed or compiled runtime bytecode
  virtualStorageLayout: vsl,
});

if (report.collisions.length > 0) {
  // A recovered persistent SSTORE contradicts the VSL.
}
```

`virtualStorageLayout` is the full-diamond VSL generated by Compose. Runtime
bytecode may be `0x`-prefixed or unprefixed.

## Report

- `collisions`: proven contradictions in root slot, offset, type width, packing,
  or container/value shape.
- `validatedVariables`: recovered writes that match a declared VSL variable.
- `uncertainScopes`: concrete persistent storage scopes that cannot be compared
  conclusively.
- `diagnostics`: storage access for which no concrete root could be recovered.
- `delegatecallWarnings`: non-blocking delegatecall evidence that needs runtime
  context from the host.

The WASM API is local and synchronous. It does not make RPC calls. Compose is
responsible for deciding whether to fetch runtime code or storage for a
delegatecall follow-up.

## Development

The package artifact is generated from the Rust project root:

```sh
npm run build
npm test
```

Publishing requires the Rust Wasm target and `wasm-pack`, which are development
dependencies only. End users install the generated package normally.
